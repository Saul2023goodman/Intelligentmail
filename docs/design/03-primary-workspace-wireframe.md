## 1. 设计命题（Design Thesis）

**Visual thesis**
> 夜间管制室的气质，不是航空主题：一整块安静、深色、低噪声的态势台，操作员是唯一的值班人。任务按所处阶段自动归轨，位置即状态；整屏只有一盏琥珀灯，点亮"现在需要你决定的事"。

**Content plan（单屏职责，自上而下）**
1. 环境栏：当前 Campaign、邮箱链路状态、标准时钟；
2. 暂停横幅：仅当执行流中断时出现，给出该情况下唯一有效的动作；
3. **态势看板：所有在制任务按阶段分轨，一屏完成扫描与处置**；
4. 检查栏：选中任务的全部证据与当前唯一可执行动作；
5. 记录流：全局唯一的操作与观测流水，不在他处重复。

**Interaction thesis（三个决定气质的动效）**
1. **归轨滑动（Track Glide）**：状态流转时任务卡平滑滑入目标轨道——位置变化本身就是状态反馈，不需要再读一枚状态徽章；
2. **同步扫描（Sync Sweep）**：邮箱只读刷新时一道微光扫过列表，新到的回复/观测先以空心轮廓淡入，关联确认后落定为实心标记；
3. **精确确认（Precision Confirm）**：授权时要求操作员输入任务编号完成"复诵式"确认——这是从空管"许可必须复诵"借来的交互理念，但界面只说"输入任务编号以确认"。

**理念边界（本版对 v0.2 的纠偏）**

| 借（理念） | 不借（表皮） |
|---|---|
| 管制员的态势感知：一眼定位待办与风险 | 呼号、进程单、跑道、塔台等航空道具与术语 |
| 进程单位置即阶段 | 把任务叫成"航班"、把任务卡做成纸质飞行单 |
| 放飞许可必须复诵、不得口头代授权 | CTOT、NOTAM、squawk 7700、EFC、coast 等黑话 |
| 雷达有覆盖范围与盲区，视距外不保证无目标 | 拟物雷达屏幕、扫描动画当装饰 |
| 流量管理：窗口、间隔、容量 | 机场发车牌造型 |
| 单一频率、单一值班人的专注感 | 航空主题插画、徽章、纹理 |

界面所有文案以 [CONTEXT.md](../../CONTEXT.md) 领域词汇为准：任务、制备、就绪、确认、执行、暂停、结果未知、对账、跟进。

## 2. 空管理念 → 设计原则的转译

| 运营现实（SmartMail） | 空管中的对应原理 | 在本界面的落地（无航空词汇） |
|---|---|---|
| Prepared → Ready → Confirmed → Sent | 目标按阶段分区，位置即状态 | 七条阶段轨道，归轨即分类 |
| Confirmation 绑定精确内容、可复诵 | 放飞许可内容必须逐字复诵 | 精确确认弹层：输入任务编号解锁发送 |
| Execution Flow 暂停 | 跑道关闭时全频率只有一条指令 | 全局暂停横幅，一种原因只给一个主动作 |
| Unknown Outcome 禁止盲重试 | 未识别目标先识别，不据猜测处置 | 待核实轨 + 唯一动作"对账"，空心轮廓视觉 |
| Evidence Coverage 有边界 | 雷达视距与盲区 | 覆盖度与"未发现重复"结论同屏，盲区列出 |
| Sending Plan：窗口/间隔/日上限 | 流量控制的时刻、间隔、容量 | 发送时刻表：违反约束即时拒绝并指名 |
| Sent Record 不可变 | 飞行数据记录只追加 | 已发送轨只读，附锁定标识 |
| 单一值班人、单一频率 | 一台仪器一条信息通道 | 全站一盏琥珀灯；同类信息全站唯一出口 |
| 异常需要立即被看见 | 紧急应答机必须跳脱背景 | 受阻卡片左缘红色信号条 + 克制脉冲 |

**信息去重审计（v0.1 → v0.3，继续生效）**

| # | v0.1 中的重复/无效信息 | 处置 | 理由 |
|---|---|---|---|
| 1 | **Institution 院校**（列表列、筛选器、详情头部三处） | **全部移除**。它只是 Supervisor 的从属属性，对"下一封邮件怎么处理"零决策价值，且与收件人域名高度重复；仅在检查栏主管详情里作一行可展开弱文本 | 用户点名的无效信息；判别标准：同一决策周期内不会被它改变动作 |
| 2 | 页面头摘要句（42 tasks · 7 blocked…） | 删除 | 与侧栏、轨道头计数重复；计数唯一来源 = 轨道头 + 导航队列灯 |
| 3 | 状态：行内圆点 + 文字徽章 + 步进条（三重） | 合并为**位置**：卡片所在轨道即状态；只在有异常时挂标记 | 位置编码是最快的状态通道 |
| 4 | 邮箱地址：行内 + 顶栏 + 详情面板 | 行内移除；环境栏显示链路与地址；检查栏显示一次 | 单人单机，邮箱是环境不是行属性 |
| 5 | 查重：表格列 + 筛选 + 面板分区 | 卡片上一个冲突标记；详情只在检查栏"查重与覆盖"块 | 无重复是默认态，不该占列 |
| 6 | 跟进：表格列 + 队列 + 资格行 | 统一为跟进轨 + 卡片上的到期计时标 | 同一事实三处口径 |
| 7 | 最近事件：详情 + Dashboard + 通知 | 底部记录流唯一出口；其余处只放深链 | 流水只应有一条 |
| 8 | 覆盖度：行内小图标 + 面板进度条 | 仅在结论旁出现一次（检查栏 / 观测记录） | 覆盖度是结论的限定语 |
| 9 | Blocker：计数列 + 阻断轨 + 异常页 | 信号条 + 受阻轨；点开即见原因 | 计数与状态同源 |
| 10 | 筛选：下拉 + chip 排 + Clear | 单行 chip，激活即筛选 | 控件即状态 |
| 11 | 计划槽位：Dashboard 预告 + 计划页 | 仅发送时刻表；Dashboard 只显示"下一时刻"单值 | 同一份排程不两处展示 |
| 12 | 刷新按钮：页面头 + 邮箱页 | 环境栏唯一同步入口（只读，永不改变外发状态） | 动作收敛 |

## 3. Design Tokens（视觉母体的物质层）

### 3.1 色彩——"一台仪器，一盏琥珀灯"

| Token | 值 | 用途 |
|---|---|---|
| `--surface-0` | `#0A0E0F` | 页面底 |
| `--surface-1` | `#0F1517` | 轨道带、环境栏 |
| `--surface-2` | `#141B1E` | 任务卡、检查栏、时刻表 |
| `--hairline` | `rgba(150,180,188,.12)` | 唯一允许的分隔线强度；内部默认无线 |
| `--ink-1` | `#E7EFF1` | 编号、值（最高亮） |
| `--ink-2` | `#9DB0B7` | 标签、收件人（次亮） |
| `--ink-3` | `#5C7078` | 元信息、单位、时间（60% 降噪） |
| `--amber` | `#FFB02E` | **唯一强调色**：待决策、计划时刻、主操作、焦点描边 |
| `--amber-dim` | `rgba(255,176,46,.14)` | 琥珀底纹，不使用实心块 |
| `--confirmed` | `#2FE6A6` | 功能色（非装饰）：已证实发送、关联成功、同步扫描微光 |
| `--danger` | `#FF5348` | 仅受阻标记与危险动作 |
| `--unknown` | 虚线描边 `--ink-2` | 结果未知/歧义：空心轮廓 + 虚线，禁用红绿判断 |

规则：除 `--confirmed`（事实成立）与 `--danger`（报警）两个受语义约束的通道外，全站只有琥珀一个强调色；发光只允许出现在任务编号、受阻信号与主操作键上，"全员不发光"。

### 3.2 字体与排印

- 两族字体：**IBM Plex Sans**（标签/正文）＋ **IBM Plex Mono**（编号、时刻、地址、SHA、计数——数字 tabular-nums）。
- 字号：12 / 13（卡片正文）/ 15（轨道头）/ 22（检查栏标题）/ 11（元信息，字距 +0.04em，大写标签）。
- 大标签采用「小号大写 + 字距」而非加底色块；禁止标题实心底图。

### 3.3 间距、层级与动效

- 4pt 栅格；卡片内边距 10/12；轨道间距 8；检查栏组距 20。
- 层级三级：**编号/时刻最亮 → 内容次亮 → 标签/单位 60% 灰**；用明度而非边框分层。
- 阴影仅一种：检查栏/弹层的轻微抬升（`0 8px 28px rgba(0,0,0,.45)`）；卡片之间无阴影。

| 动效 | 参数 | 触发 |
|---|---|---|
| 归轨滑动 | 260ms `cubic-bezier(.22,1,.36,1)`，layout 动画 | 阶段流转 |
| 同步扫描 | 1400ms ease-out，扫后 120ms 错落淡入 | 邮箱只读刷新 |
| 标记落定 | 200ms，空心轮廓 → 实心 | 回复/观测关联成功 |
| 确认弹层 | 160ms 上移淡入；发送时琥珀脉冲一次 | 精确确认 |
| 受阻脉冲 | 2.4s 不透明度 .35↔1，每屏同时 ≤ 4 个 | 阻断/结果未知 |

全部遵守 `prefers-reduced-motion`：扫描改静态微光、滑动改瞬切、脉冲常亮。

### 4.1 分区说明

| 区 | 设计 |
|---|---|
| 环境栏（52px） | 环境信息唯一出口：Campaign 切换（切换需确认）、邮箱链路四态、UTC/本地双时钟、`同步观测`（只读，绝不改变外发状态）、`＋导入`（仍强制显式选 Campaign+Student）。无口号、无光效横幅 |
| 左侧导航（可折叠 56px） | 沿用 IA 九区：态势 / 任务 / 制备 / 发送计划 / 执行 / 邮箱与对账 / 回复与跟进 / 报告 / 设置；仅挂跨页队列灯（阻断、暂停、待核实、跟进到期），不重复轨道计数 |
| 暂停横幅 | 暂停时才出现、不可关闭；左侧 4px 红色竖条 + 事实文案 + **该原因下唯一有效主动作**；多条时展开队列，按 结果未知/认证 > 阻断 > 过期 排序 |
| 视图切换 | 看板（默认）/ 列表（高密度表，批量核对用）；两视图同源数据、同筛选 |
| 筛选行 | 单行 chip，全部取报告枚举口径；激活态用琥珀左缘线而非实心填充 |
| 阶段轨道 ×7 | 每条：名称 + 一句操作语义 + 计数 + 横向滚动的卡片流；风险从上到下排序，已发送置底 |
| 检查栏 | 见 §7；无选中时显示该轨道说明与键盘提示，不放装饰插画 |
| 记录流 | 全局唯一流水（28px 收起 / 160px 展开为表）；点击深链到证据；外部结果以证据为准，记录流只报"发生了什么" |

### 4.2 计数口径（全站唯一）

- **轨道头计数**：阶段分布（板上事实）。
- **导航队列灯**：只显示需要跨页追办的四个数——阻断、暂停、待核实（结果未知+歧义）、跟进到期。
- 其他位置（页头、卡片角标、通知）不再出现计数。

## 5. 任务卡（Task Card）解剖

卡片是核心交互件，不是装饰卡：常态无底框，仅靠 `--surface-2` 底与 8px 间隙成组；选中或告警才出现线条。

```text
常态（就绪待确认）                              告警态（受阻）
┌──────────────────┐                          ┌──────────────────┐
│ T-1055      10:00 │                          │ ┃T-1042      09:00a│ ← 左缘：琥珀=待确认 / 红=受阻 / 虚线=待核实
│ 李明               │                          │ 王宇               │ ← Student
│ → 陈伟旺           │                          │ → A. Smith         │ ← Supervisor（无院校）
│ [ 确认发送  C ]   │                          │ ✕2 · 冲突 · CV 412KB│ ← 标注行：仅异常/关键事实
└──────────────────┘                          └──────────────────┘
```

| 位 | 内容 | 去重规则 |
|---|---|---|
| 左上 | 任务编号（等宽字体） | 全界面稳定主键，搜索/确认均用它 |
| 右上 | 仅在有计划时显示发送时刻；无计划留空 | 不渲染无意义时间 |
| 中部 | Student → Supervisor 两行 | 邮箱地址不在此出现；**不含院校** |
| 标注行 | 只写"改变下一个动作的事实"：阻断数与类型、冲突、缺附件、计划时刻；否则显示该轨主动作键 | 默认态（无异常无冲突）在卡片上零噪声 |

**修订痕迹**：时间调整或 Rewrite 后，旧值以删除线 + `--ink-3` 保留、新值以琥珀书写（只在检查栏展开时可见，卡片上只在右上时刻角标一个小 `a`）；被取代的制备不进任何轨道，只沉淀在检查栏的"版本记录"。

## 6. 轨道语义与每轨唯一主动作

| 轨道 | 进入条件 | 卡片主动作（快捷键） | 禁止动作 |
|---|---|---|---|
| 待核实 | 结果未知 / 歧义回复 / 歧义匹配 | `R` 对账或裁决 | 执行、重试、任何外发 |
| 受阻 | 存在阻断项 | `E` 就地修正（字段/身份/附件） | 确认 |
| 就绪待确认 | 就绪且查重通过/已裁决 | `C` 打开精确确认 | 一键即发（无此路径） |
| 已确认 | 有效确认 | 查看许可 / 加入执行批次 | 直接编辑（编辑即失效，回到就绪轨） |
| 执行中 | 尝试进行中 | 检查栏展开三阶段证据；暂停时动作收归横幅 | 越过暂停继续 |
| 已发送 | 已发箱唯一匹配 → 冻结记录 | 只读 / 发起链接的跟进 | 改写、重新确认、重复发送 |
| 跟进中 | 跟进计时中 / 已到期 | 到期后：制备 → 独立精确确认；收到普通回复即终态 | 自动发送、按初邮查重 |

流转一律伴随归轨滑动；被规则拒绝的流转（如存在活跃尝试时改写）不弹空泛警告，而是卡片轻摇 180ms 并在检查栏显示被拒条款。

## 8. 精确确认弹层（授权的唯一入口）

理念借自空管复诵：许可内容逐字呈现，操作员输入**任务编号**完成确认，杜绝"勾一下就发"。批量授权逐条确认，不能整批跳过。

```text
┌ 发送确认 · 请逐字复核并输入任务编号 ────────────── 1 / 4 ────── ✕ ┐
│                                                                    │
│  任务      T-1042                                                  │
│  发件人    wangyu@163.com                                           │
│  收件人    prof.smith@ntu.edu.sg                    ³ 主管已知地址   │
│  主题      PhD supervision enquiry – Wang Yu                       │
│  附件      CV_WangYu.pdf   412 KB   sha 9f2a…c13  ◇ 已冻结         │
│            成绩单.pdf      288 KB   sha 77bd…09a  ◇ 已冻结         │
│  查重      未发现重复                                               │
│            覆盖度 已发箱 5/5 页 · 收件箱 3/5 页   ⓘ 盲区见明细      │
│  ┌ 正文 — 冻结快照（需滚动到底）──────────────────────────────┐ │
│  │ Dear Professor Smith, …                                       │ │
│  └────────────────────────────────────────────────────────────────┘ │
│  执行方式  ◉ 确认后立即发送    ◎ 加入发送计划                       │
│  有效期    至 [ 2026-09-16 18:00 ]（可选）                          │
│                                                                    │
│  输入任务编号 T-1042 以确认：                                       │
│  [ T-1042______________________________________ ]                  │
│                                       [ 取消 ]   [ 确认发送 ↵ ] 锁定│
└────────────────────────────────────────────────────────────────────┘
```

- 编号完全匹配前确认键锁定；Enter 不跳过、Esc=取消；批量时 `1 / n`，确认一张滑走一张。
- 弹层内全部只读；要改内容先取消、回检查栏编辑，编辑使旧确认失效（回到就绪轨）。
- 提交前 Native Host 复核的摘要与弹层冻结的是同一组 SHA——看到的内容 = 提交的内容。
- 过期时刻的恢复同样走此弹层改新时间后重新确认；系统永不把过期计划降级为立即发送。

借用"发车时刻牌"的高密度排版理念（时刻等宽对齐、状态一列收口），但使用业务语言与常规组件。

## 10. 暂停横幅、链路状态与空态

**暂停横幅：五种原因 → 唯一主动作**（与 Workflow Map F6 一致）：结果未知→`立即对账`；登录/验证中断→`我已完成登录`；新阻断/冲突/回复→`查看证据`；确认过期→`调整时间并重新确认`；执行失败→`查看证据 / 记录人工接管`。文案结构固定：对象 + 事实 + 被阻止的动作（如"已阻止盲目重试"）。

**邮箱链路四态**：`● 已连接`（地址一致）/ `◐ 需要登录`（未登录或验证码）/ `◆ 账号不符`（标签页邮箱与登记不一致，零落库）/ `○ 桥接不可用`。点击进邮箱与对账页，能力矩阵逐项显示 禁用/已验收；🧭 定时/取消/替换/撤回四项独立禁用行。

**空态**：首次使用 = 三步引导（建 Campaign → 登记学生与邮箱 → 导入首批材料），纯排版无插画；筛选无结果 = 一行说明 + 清除筛选；本地暂停期间其余轨道照常作业，外部定时承诺 🧭 在执行页置顶，本地暂停 ≠ 取消外部承诺。

## 12. 交互、可访问性与诚实性

- **键盘流**：`J/K` 移动卡片，`E` 修正，`C` 确认，`R` 对账/裁决，`A` 附件，`/` 搜索，`⌘K` 命令面板；主动作有可见快捷键提示。
- **乐观更新边界**：仅本地字段纠正可乐观更新并可撤销；确认、执行、对账等待核心返回；外部结果只信证据页，记录流/toast 不承载成败结论。
- **危险动作文案公式**：动作 + 对象 + 不可逆后果（例："停止 A-1025 将释放该尝试；之后才可改写制备，且不改变邮箱实际状态"），红色，二次确认，不做"不再提示"。
- **可访问性**：状态一律颜色+形状+文本三编码；红与琥珀在深底对比度 ≥ 4.5:1（小字用提亮档）；横幅 `role="alert"`；脉冲与扫描支持 reduced-motion；图标键均有 aria-label。
- **数据诚实**：结果未知永远是虚线空心、不允许成功/失败语义；"未发现重复"必须挂覆盖度牌；🧭 未验收能力可见不可点并标注验收状态；无任何 AI/猜测类文案与入口。

## 13. 版本沿革与下一步

- **v0.1**：持久化主从表格——信息密度好但视觉平庸、状态三重表达、信息多处重复。
- **v0.2**：航空化拟物——理念正确但表皮过重（呼号/进程单/CTOT/7700 等术语伤害了业务表达）。
- **v0.3（本版）**：**只留空管理念**——态势台分轨、位置即状态、单灯原则、复诵式精确确认、覆盖盲区诚实、唯一记录流；全部标签回归领域术语。IA（文档 02）的九区结构与命令边界映射不变，看板与列表是同一数据的两种工作密度。

**建议下一步（评审通过后，仍不改核心代码）**：
1. 用"晨间批处理"与"结果未知恢复"两个真实场景走查看板，校准轨道顺序与卡片信息裁剪；
2. 出高保真视觉稿（看板 + 精确确认 + 发送时刻表三屏），验证深色底上琥珀/绿/红的气质；
3. 可点击原型只做三条路径：清除阻断 → 精确确认 → 暂停后对账；
4. 前端编排层与 headless 命令/查询边界的 API 映射（核心边界已是稳定接口，视图只做形态映射）。
