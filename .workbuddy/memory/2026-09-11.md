## Ticket 03: Resolve readiness Exceptions and attachments (resolved)

Implemented ticket 03 at the same seam, TDD red→green per vertical slice. Final run: **63 tests passed, no skips**, with the representative archive. New tests in `tests/test_readiness.py` (28 tests) plus an added opt-in representative test.

**Confirmed design decisions with the user before testing** (the user overrode the ticket's "required attachment" wording):
- **Attachment slots are advisory only.** Body/source evidence creates a *suggested* slot (`Student CV`) with the best filename candidate; the system must not finalize it. The operator confirms/replaces/adds/removes. Slots NEVER block readiness and there is NO `require` command — only an explicit requirement would make one mandatory, and none is implemented.
- **Identity conflicts get an explicit command**: `task confirm-identity` clears that Task's `identity_ambiguity` and revalidates its Preparations. No guessing, no merging; per-Task.
- Seam approved as proposed: `exceptions list/show`, `task confirm-identity`, and Preparation-scoped `set-subject` / `set-recipient` / `suggest` / `confirm` / `attach` / `add-attachment` / `remove-attachment`.

**Key implementation choice**: readiness findings were centralized in one `_revalidate(preparation_id)` step that recomputes from current state; `_store_preparation` and every correction call it. This is what makes "revalidate the complete Preparation after correction" true and removed the old inline finding logic.

**Added**: schema `corrections`, `attachment_slots` (`label`, `declared`, `basis`, `suggested_source_id`), `attachments` (byte snapshot + sha256); `documents.attachment_declarations` (regex on "I have attached my X", stop-word trimmed); core `list_exceptions`/`get_exception`/`confirm_task_identity`/`set_subject`/`set_recipient`/`suggest_attachment_slots`/`list_attachment_slots`/`confirm_attachment`/`set_attachment`/`add_attachment_slot`/`remove_attachment_slot`/`read_attachment`; `get_preparation` now returns `corrections` + `attachment_slots`; preview prints an `Attachments:` line.

**Representative results**: 17 Preparations each get one advisory `Student CV` slot with the single candidate `姚思培/Sipei Yao - CV.docx`; 0 auto-confirmed; 4 `invalid_recipient` Task Exceptions listed with workbook evidence (only Morton's Task has a Preparation → `missing_subject`); Susanna Castleden recipient conflict corrected to recorded address; confirmed CV SHA-256 `1a04f288…d67e` (28,258 B) identical to the preserved Source Material.
